# like-bot-v2

네이버 블로그 답방 유도 도구. 내 블로그 계정으로 관심 있는 주제의 최신 글에 공감을
누르면, 그 블로그 주인이 방문 기록을 보고 내 블로그를 찾아온다 — 이 왕복이 이 도구의
전부다. 자세한 배경과 설계 근거는 [CLAUDE.md](CLAUDE.md)에 있다.

## 내려받기

**[최신 릴리스에서 `like-bot-v2-*.zip` 받기](https://github.com/embed-Rayn/like-bot-v2/releases/latest)**

Windows 10 / 11 64비트. 파이썬도, 크롬도 따로 설치하지 않는다 — 브라우저까지 안에 들어
있다. 압축을 풀고 `like-bot-v2.exe`를 실행한다. 압축 파일 약 280MB, 풀면 약 645MB.

> 처음 실행할 때 Windows SmartScreen이 "Windows의 PC 보호"를 띄운다. 서명하지 않은
> exe라서 그렇다. **추가 정보 → 실행**으로 넘어간다.

## 쓰는 법

1. **네이버 아이디** — 내 블로그 계정 하나만 쓴다. 여러 계정에 나눠 누르면 답방이
   여러 블로그로 흩어져서 목적 자체가 사라진다. **비밀번호는 묻지 않는다** — 세션이
   없으면 로그인 창이 열리고, 거기서 직접 로그인하면 된다. 앱이 대신 입력하면 네이버가
   "보안을 위해 추가 확인"을 띄우고 반복되면 계정 보호 조치로 이어지기 때문이다.
   한 번 로그인하면 세션이 저장돼 다음부터는 로그인 창이 뜨지 않는다.
2. **키워드** — 내 블로그 주제와 겹치는 말로. 답방 확률이 여기서 갈린다.
3. **기간** — 최근으로 좁힐수록 "지금 활동 중인" 블로거가 걸린다.
4. **방문 상한 / 블로그당 공감 수** — 많은 블로그에 조금씩이 적은 블로그에 많이보다
   답방이 잘 나오고, 스팸으로도 덜 보인다.
5. **드라이런에 체크하고 한 번 돌려 본다.** 공감 버튼을 찾기만 하고 누르지는 않는다.
6. 그다음 방문 상한 3, 블로그당 공감 1로 작게 한 번. 그 뒤에 늘린다.

기본값은 방문 상한 200, 블로그당 공감 3, 분당 6회다. 분당 6회는 일부러 낮게 잡은
출발점이다 — 올리기 전에 [알아 둘 것](#알아-둘-것)을 읽을 것.

### 화면

키워드 패널이 넷이고, 실행은 계정 하나로 그 키워드들을 동시에 훑는다. 패널마다 있는
▶는 "이 키워드 하나로만 실행"이고, 위쪽 **▶ 전체 실행**은 넷 전부다. 계정 하나에
걸린 속도 제한을 여러 패널이 나눠 쓰므로, 패널을 늘려도 공감이 빨라지지는 않는다.

**■ 정지**를 누르면 진행 중인 블로그를 마치고 멈춘다. 글 중간에 끊고 나가면 네이버
쪽에서 보기에 더 이상하다.

실행이 끝나면 아래 사유 중 하나가 뜬다.

| 사유 | 뜻 |
| --- | --- |
| 방문 상한 도달 | 정상 종료. 정해 둔 만큼 다 돌았다 |
| 검색 결과 소진 | 정상 종료. 그 키워드·기간에 더 볼 블로그가 없다 |
| 사용자 중지 | ■ 정지를 눌렀다 |
| 차단 의심 — 중단 | **스스로 멈춘 것이다.** 사유 끝의 `(마지막: …)`를 볼 것. `계정 제한 의심`이면 재로그인은 소용없다 — 네이버에서 풀어야 한다 |
| 로그인 풀림 — 중단 | 세션이 정말 만료됐다. 다시 실행하면 로그인 창이 뜬다 |

### 로그인

앱에 적는 **네이버 아이디**는 세션 파일과 방문 기록을 계정별로 가르는 데만 쓴다.
**네이버 로그인 폼에는 앱이 아무것도 대신 입력하지 않는다.** 자동 입력이 "보안을 위해
추가 확인" 화면을 부르는 바로 그 동작이고, 그 화면은 어차피 사람이 푼다 — 자동 입력이
계정에 남기는 것은 실패한 로그인 시도 기록뿐이고, 그게 쌓이면 계정 보호조치가 된다.

- **세션이 살아 있으면** 로그인 화면을 아예 거치지 않는다.
- **세션이 없거나 만료됐으면** 브라우저 창이 열린다. 거기서 직접 로그인하면 되고,
  끝나는 대로 하던 일을 이어서 한다. 한 번 하면 세션이 저장돼 다음부터는 안 뜬다.

기다리는 동안 **창을 닫으면 그 자리에서 중단된다.** 닫지 않으면 최대 30분까지
기다리고, 1분마다 남은 시간을 알린다. 보호조치 본인확인처럼 오래 걸리는 일을 하는
도중에 창이 닫히지 않게 하기 위해서다.

추가 확인 화면을 프로그램으로 우회하려 들지 않는다 — 계정이 정지되면 답방이 0이 된다.

## 알아 둘 것

- **계정 안전이 속도보다 우선이다.** 분당 공감 수를 올릴수록 위험이 올라간다. 정지된
  계정은 트래픽을 한 명도 못 데려온다.
- **저장된 세션은 자격증명이다.** `sessions\{계정}.dat`에 로그인 쿠키가 들어 있다. 이
  파일을 가진 사람은 비밀번호 없이 로그인된 상태가 된다. 로그·스크린샷·화면 공유에
  노출됐다면 네이버 **내정보 → 로그인 기록/기기 관리에서 로그아웃**해서 폐기해야 한다.
  파일만 지우는 것으로는 무효화되지 않는다 — 세션을 들고 있는 쪽은 네이버다.
- **실행 기록에도 오류 메시지가 그대로 들어간다.** 로그 파일을 남에게 보내기 전에
  세션 값이 찍혀 있지 않은지 한 번 보고 보낼 것.
- 방문 기록은 계정별로 남는다. 상한 N은 "이 계정이 아직 안 가 본 블로그 N개"를 뜻한다.
  같은 블로그를 두 번 가지 않는 것은 예의이자 계정 안전이다.

## 저장되는 것

전부 `%LOCALAPPDATA%\like-bot-v2\` 아래에 있다. 주소창에 그대로 붙여 넣으면 열린다.

| 경로 | 무엇 | 지우면 |
| --- | --- | --- |
| `sessions\{계정}.dat` | 로그인 쿠키 (DPAPI 암호화) | 다음 실행에서 다시 로그인 |
| `logs\run-….jsonl` | 실행 하나당 기록 한 개, 최근 30개 | 진단 자료만 사라진다 |
| `logs\crash.log` | 예기치 못한 오류의 트레이스백 | 위와 같다 |
| `history.db` | 계정별 방문한 블로그 | **이미 간 블로그를 다시 간다** |
| `config.json` | 마지막 입력값 (드라이런 제외) | 기본값으로 돌아간다 |

비밀번호는 어디에도 저장하지 않는다 — 앱이 받지 않기 때문이다. 로그인은 브라우저
창에서 사람이 하고, 그 결과인 세션만 위의 `.dat`로 남는다.

**지우려면** 이 폴더를 통째로 지운다. 단, 세션 파일을 지우는 것만으로는 로그인이
무효화되지 않으니 네이버에서 로그아웃까지 할 것.

## 문제가 생기면

먼저 창의 **📁 로그 폴더** 버튼을 눌러 가장 최근 `run-….jsonl`을 연다. 실행 하나가 파일
하나이고, 한 줄에 사건 하나가 시간 순으로 들어 있다.

| 증상 | 볼 것 |
| --- | --- |
| 첫 실행이 한참 멈춰 있다 | 정상이다. 645MB를 처음 읽는 중이라 그렇다 |
| 백신이 exe를 잡는다 | 서명하지 않은 PyInstaller 빌드라 오탐이 잦다. 예외 등록 |
| 실행 중에 앱이 사라지고 파일까지 없어졌다 | 백신이 실행 중인 exe를 격리한 것이다. Windows 보안 → **보호 기록**에서 확인하고 복원 + 폴더 예외 등록 ([배포 문서 §6](docs/PACKAGING.md#6-백신이-배포본을-지우는-경우)) |
| 브라우저 창이 안 뜬다 | 로그의 마지막 줄을 본다. `crash.log`가 새로 생겼는지도 |
| 로그인 창에서 멈췄다 | 직접 로그인하면 이어서 간다. 최대 30분 기다리고, 창을 닫으면 중단된다 |
| 공감이 하나도 안 눌린다 | 로그의 `detail`을 본다. `계정 제한 의심`이면 계정이 막힌 것이라 재로그인·재실행 모두 소용없다(네이버에서 풀 것). `세션 만료`면 다시 실행해 로그인하면 된다. 둘 다 아니면 드라이런으로 버튼을 찾는지 본다 — 못 찾으면 네이버가 화면을 바꾼 것이다 |
| "차단 의심"으로 멈춘다 | 사유 끝의 `(마지막: …)`를 먼저 본다. `계정 제한 의심`이면 속도 문제가 아니라 계정이 막힌 것이다. 그 외에는 **분당 공감 수를 낮추고 하루 쉰다.** 어느 쪽이든 바로 다시 돌리는 것이 가장 나쁜 선택이다 |
| 실패해도 안 멈춘다 | 연속 실패 상한은 1000이다(사실상 끔). 남은 안전장치는 최근 20건 성공률 30% 미만, 네이버의 직접 차단 신호, 로그인 풀림 셋이다 |
| "연속 실패" · "성공률"로 멈춘다 | 중단 문구 끝의 `(마지막: … — 단계)`를 본다. `클릭 후 on 확인`이면 네이버가 공감을 받지 않고 있다는 뜻이라 멈춘 것이 맞다. `페이지 로딩`이면 회선 문제에 가깝다 |
| 방문 상한만큼 안 돌고 끝난다 | "검색 결과 소진"이면 정상이다. 키워드를 넓히거나 기간을 늘린다 |

네이버가 화면을 바꿔서 생긴 문제인지 확인하려면 (개발 환경에서):

```
python -m pytest -q -m contract     # 검색·RSS가 아직 그대로인지
python -m pytest -q -m browser      # 공감 버튼 셀렉터가 아직 그대로인지
```

## 못 하는 것

의도적으로 뺐거나, 애초에 불가능한 것들이다.

- **계정 여러 개를 동시에** — 답방이 여러 블로그로 흩어져서 도구의 목적 자체가 사라진다.
- **한 키워드에서 1000건 넘게** — 네이버 검색이 거는 상한이다 (실측). 더 필요하면 기간을
  나누거나 키워드를 늘린다.
- **추가 확인(캡차) 자동 통과** — 하지 않는다. 봇 탐지 우회이고 계정이 날아간다.
- **무인 실행 / 백그라운드** — 로그인 확인에 사람이 필요해서 창이 보이는 채로 돈다.
- **Windows 외 (macOS · Linux)** — 배포본은 Windows 전용이다. 소스는 돌지만 검증하지 않았다.

## 개발

```
python -m pip install -e ".[dev]"
python -m pytest -q                      # 단위 테스트 (네트워크·브라우저 없음)
python -m pytest -q -m contract          # 실제 네이버, 비로그인
python -m pytest -q -m browser           # playwright install chromium 필요
python -m desktop.app                    # 앱 실행
python tools/dryrun.py <ID> "<키워드>"    # 로그인해서 버튼만 확인, 클릭 안 함
```

exe 빌드는 [docs/PACKAGING.md](docs/PACKAGING.md)를 볼 것 — 빌드 절차, onedir을 쓰는
이유, 백신 오탐 대응까지 여기에 있다.
